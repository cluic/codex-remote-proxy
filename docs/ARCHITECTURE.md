# Architecture

## M2E/V8 Web And Metrics Extension

The packaged Web application is rebuilt from `node/ui-src/` with Vite, React, and TypeScript at development time. Production still serves exactly three same-origin static files from the existing Admin Server: `ui/index.html`, `ui/app.js`, and `ui/styles.css`. Vite, TypeScript, React source, and frontend development dependencies are not runtime services and are not published as source. The build emits no dynamic chunks, source maps, remote assets, telemetry, service worker, or server-side rendering, and the existing strict CSP is not relaxed.

Operational Metrics is a third plane beside Activity and Capture. Activity remains sanitized control-plane history. Capture remains opt-in detailed request persistence and has no Web management surface in this MVP. Metrics is always-on anonymous aggregation: the Worker emits one strict, non-blocking observation at a request terminal state; WorkerManager validates it and resolves the immutable request generation to its Provider; Supervisor aggregates and persists bounded hourly buckets; Admin exposes a read-only positive projection.

The Worker observation contains no Provider ID or request-derived string other than one credential-screened bounded model ID. The private Supervisor snapshot carries Provider ID outside the credential-bearing Worker settings, and WorkerManager retains only a bounded generation mapping. Metrics IPC, aggregation, persistence, and Admin projection are all non-critical: failure increments bounded quality/degradation state but cannot fail proxy forwarding, Provider switching, Worker lifecycle, or Supervisor shutdown.

## Implemented Overview

The approved design splits the local application into a long-lived supervisor control plane and a replaceable proxy worker data plane.

```text
Browser UI / crp CLI
          |
          v
Supervisor (127.0.0.1:15101)
  - Admin API and static UI
  - Provider registry
  - Independent provider-model cache
  - Anonymous hourly Metrics aggregate
  - Credential adapters
  - Codex config adapter
  - Worker manager and activity log
          |
          | IPC + immutable config snapshots
          v
Proxy Worker (127.0.0.1:15100)
  - HTTP/SSE forwarding
  - Authorization rewrite
  - Per-request provider snapshot
          |
          v
Active OpenAI-compatible upstream
```

## Invariants

1. Codex keeps `model_provider = "OpenAI"` so existing OpenAI-tagged threads remain visible.
2. Codex keeps the fixed proxy address `http://127.0.0.1:15100` after bootstrap.
3. Provider activation affects new requests only; in-flight requests retain their starting snapshot.
4. The supervisor remains available while the worker restarts.
5. Worker IPC receives only the selected active provider credential; broader inherited process-environment minimization remains separate L3 hardening.

## Module Boundaries

Landed in Tasks 2 through 11:

- `shared/paths`: derives CRP registry, independent provider-model cache, anonymous Metrics aggregate, lower-level private credential-adapter, state, control token, activity, log, Codex configuration, and Codex auth paths from one home root.
- `shared/errors`: defines stable `CrpError` fields and safe public serialization for known and unknown failures. Detached startup messages use an exact version-1 envelope and static contract allowlist; unknown codes, text, actions, statuses, details, extra fields, oversized payloads, or malformed values are rejected rather than projected.
- `codex-config`: preserves custom providers and source line endings while idempotently bootstrapping the fixed OpenAI provider entry. Inspection and patching share one semantic statement scanner for supported root, quoted, and dotted provider bindings; invalid UTF-8 and malformed or ambiguous selected-provider bindings fail before writes, without claiming whole-document TOML validation. A missing real parent/config is created privately (`0700` directory and `0600` file on POSIX), atomically, with no backup; a repeated bootstrap is byte-identical. Existing files retain the sidecar lock, no-follow descriptor/identity and source-race checks, exclusive timestamped adjacent backup, and atomic mode-preserving replacement. Filesystem failures project only stable `CODEX_CONFIG_*` contracts.
- `codex-history-repair`: reads the root Codex `model_provider` and its corresponding `base_url` from the same locked snapshot. A same normalized URL skips history repair even when the provider name changes; a different or missing existing effective URL discovers exact active/archive rollout records and locked SQLite row sets. A nonempty set receives byte-exact rollout backups, exclusive fsynced SQLite logical snapshots, and a durable private pending journal before config publication; an empty set commits config without journal. Pre-rename metadata durability, parent-directory fsync, fixed clearing markers, source/target hashes, config-hash checks, and lock ownership support idempotent forward recovery. CRP provider-registry operations never call this module.
- `provider-schema`: canonicalizes safe URLs, validates auth and extra-header syntax plus complete stored profiles, and builds public provider objects from an explicit allowlist.
- `provider-registry`: synchronously manages provider CRUD, test state, and the active provider ID through strict schema-version-2 documents, lock-serialized reload-before-mutate writes, refreshed defensive reads, and same-directory fsynced `0600` atomic replacement.
- `provider-model-cache`: persists exact schema-version-1 catalog entries separately from registry schema 2. The file is capped at 16 MiB and 512 provider entries; each entry retains only provider ID, a credential-free source fingerprint, fetch timestamp, and at most 2,000 bounded unique model IDs. Public reads project `missing`, `fresh`, or `stale`; mutation uses the same conservative private lock, atomic replacement, and committed/degraded rules.
- `credential-store`: exposes native and schema-version-1 private adapters behind one asynchronous get/set/has/delete contract without enumeration. The public Supervisor constructs native storage only and fails closed; the file adapter is limited to trusted dependency injection until a separately reviewed L3 startup-consent path exists. Native operations never replay into the independent file namespace.
- `native-keyring`: lazily loads synchronous `@napi-rs/keyring` entries during construction under service `org.cluic.codex-remote-proxy`, supports injected loaders/factories, preserves backend failures only as internal causes, and exposes safe stable errors.
- `file-credential-store`: validates a real private parent and regular private file, opens and identity-checks a descriptor before reading, validates exact secret-only documents, refreshes reads, and serializes clone-before-commit mutations with exclusive `0600` lock and temporary files.
- `runtime-settings`: accepts only positive, strictly increasing safe-integer generations, clone-and-freezes plain settings before replacing one active reference, and exposes only configured state plus generation publicly.
- `capture-store`: starts idempotently, establishes a synchronous SHA-256 fingerprint of the runtime-config file bytes, immediately reloads that file to reconcile a rewrite during startup, and then compares content every 500 ms with a 100 ms debounce before reloading. The fingerprint describes only runtime-config content (or a stable read-error code), never capture database content. A desired `dbPath` change while a database is active sets `captureRestartRequired` and leaves the active database path unchanged until restart. `close()` clears the polling interval, pending debounce, and fingerprint before closing the database.
- `proxy forwarding`: optionally captures exactly one runtime snapshot before request-body listeners and pins target, transport, request ID, authentication, extra headers, TLS, timeout, capture context, and logs for that request. Base and incoming URLs are joined through parsed URL components, preserving encoded paths and combined query parameters while emitting one path separator for root, `/v1`, and trailing-slash bases. Static configuration remains the generation-zero compatibility path. Dynamic health exposes only runtime and capture public state; an unconfigured source never falls back to the static upstream.
- `worker-protocol`: validates exact version-1 parent messages (`configure`, `drain`, `shutdown`, `status`) and child messages (`ready`, `configured`, `drained`, `status`, `fatal`, `metric`). Configure accepts HTTPS or explicit loopback HTTP only, requires HTTP-token authentication fields, validates the exact final authentication value with Node header rules, and rejects sensitive or authentication-conflicting extra headers. A metric child message carries only the fixed anonymous observation contract; its sanitized log projection omits the observation. Resolved settings are accepted only inside parent configure messages; other child output contains only allowlisted lifecycle state and stable public errors, and invalid input receives the fixed `worker-fatal` correlation ID.
- `proxy-worker`: creates one runtime settings source and forwarding app after the first valid configure, binds only then, applies strictly increasing generations while ready or running, rejects configure once drain begins, tracks in-flight requests independently of later phase changes, closes the listener and idle keep-alive connections during drain, acknowledges repeated drain requests without leaving the drained phase, closes capture and IPC resources during shutdown, and bounds forced cleanup after parent disconnect even when graceful shutdown is already waiting so a hanging upstream cannot orphan the worker.
- `worker-manager`: serializes lifecycle operations, validates restart snapshots before disturbing the current worker, validates every child message before use, correlates immediately observed acknowledgements by request ID and child epoch, cancels waiters on send failure, confirms configuration health before running, drains and escalates termination within deadlines, retains child control after termination timeout, and proves the fixed port free before replacement. It retains a bounded generation-to-Provider mapping and attributes anonymous observations without sending Provider IDs to the Worker. Unexpected exits use a bounded rolling crash window, then enter the Supervisor-injected Codex readiness gate before spawn; stop/close invalidate queued recovery generations, and private readiness failures remain outside public state.
- `activity/migration/provider-service`: persists a bounded sanitized event allowlist, transactionally migrates descriptor-validated legacy files, serializes provider CRUD/test/activation/model-refresh compensation, and exposes start/stop/restart facades that resolve only the active credential and advance confirmed generations. Model refresh performs a bounded authenticated no-redirect `GET <base>/models`, rejects any model ID containing the complete request credential before persistence or projection, persists only a validated catalog, leaves the last good cache intact on failure, and never changes test/activation/Worker state. A cache commit followed by cache-lock or Activity cleanup failure returns `PROVIDER_MODELS_COMMITTED_DEGRADED` without undoing or misclassifying the cache and preserves a safe underlying repair action. CLI-requested successful tests may select the first provider through a registry compare-and-set only while the Worker is stopped; selection never starts or configures the Worker. A saved test result whose registry-lock or Activity cleanup fails returns `PROVIDER_TEST_COMMITTED_DEGRADED` and does not continue to initial selection. Committed primary errors remain authoritative if Activity is also unavailable. Distinct credentials across legacy sources fail as `MIGRATION_INPUT_INVALID` before backups, credential access, registry persistence, or source mutation; Activity records that same stable code without values.
- `session-auth`: owns one private 32-byte control token plus in-memory expiring browser session/CSRF tokens; explicit cookie-session recovery rotates both browser values while preserving the original absolute expiry. Existing token files are descriptor-validated and unsafe, malformed, symbolic-link, or broadly accessible files fail closed.
- `metrics-store`: accepts only strict anonymous observations, maps them into at most 168 UTC hourly buckets, retains bounded Provider/model aggregates and fixed latency histograms, and persists an exact private schema-1 document capped at 32 MiB. Corrupt or unwritable state degrades Metrics without blocking forwarding or lifecycle operations.
- `admin-api`: enforces the exact loopback Host and Origin, disables CORS, authenticates CLI bearer and browser cookie/CSRF requests, and permits browser-session recovery only through cookie auth plus mandatory exact Origin and `X-CRP-Session-Resume: 1`. It bounds and validates request bodies, dispatches the versioned allowlisted routes, and positively projects provider, model-catalog, Metrics, worker, status, settings, diagnostics, and errors. Bootstrap, provider activation, and Worker start/restart share a FIFO Codex gate; lifecycle operations recheck strict readiness inside the gate and fail `CODEX_NOT_READY` before mutation.
- `supervisor`: requires native credential construction, composes activity and credentials before migration, constructs the registry only after migration, owns the reconstructable Metrics store, reads Codex status through no-follow descriptors plus selected-binding validation, injects the same strict Codex gate into unexpected-exit recovery, owns worker/provider/auth/Admin services, writes positive `0600` state only after Admin readiness, and performs idempotent reverse-order cleanup.
- `cli-supervisor-client`: discovers and validates the private supervisor state, authenticates to the loopback Admin API, dispatches lifecycle and provider commands, creates browser sessions for `ui`, starts a missing supervisor through an injected spawn boundary, and verifies `pid` plus `startedAt` before bounded shutdown signaling. A one-shot IPC channel races an exact allowlisted startup error against discovery, defers close fallback by one event-loop turn so a queued message wins, guards late child errors, and disconnects on success or cleanup; malformed, unknown, or missing failure messages become `SUPERVISOR_START_FAILED`. Discovery uses a 2-second liveness probe but returns a client with an independent 30-second operation timeout. Provider test/activate/delete/models selectors accept ID or an exact case-insensitive name resolved through the public list, then re-read the selected ID and reject a changed ID/name snapshot before mutation; this remains a non-atomic CLI guard rather than a server-side name API. Optional add `--model` is a two-stage create-then-test operation; creation remains committed if stage two fails, and committed-degraded test errors preserve safe repair metadata. CLI tests and V8 conditional Setup opt into initial selection; the Admin default and ordinary Provider-page tests remain false. Independent equal-key `en`/`zh-CN` dictionaries cover every human path; ordinary output retains locale precedence, while help defaults to English unless `--locale zh-CN` is explicit. Human provider/status/model/test-result formatters select only approved bounded fields and escape terminal controls. Root, command, provider-group, and provider-action help provide aligned usage/options/examples before discovery; `guide` teaches add-and-test, name selection, model refresh, first selection, and explicit Worker start. Validation occurs before Supervisor discovery, JSON failures use one language-independent safe envelope, and `start` exposes `supervisor_start`, `codex_bootstrap`, or `proxy_start` without adding an aggregate endpoint. Removed `init`, `install`, and `setup` invocations fail locally with replacement guidance and no side effect.
- `web-ui`: is authored under `node/ui-src/` as a React + TypeScript SPA and compiled by Vite into only packaged `index.html`, `styles.css`, and `app.js`. It exchanges and clears the launch fragment, implements responsive complete `en`/`zh-CN` Overview, Providers, Activity, System, and conditional Setup views, clears secret state and the current DOM value before validation or request dispatch, and uses the Admin API as its only state boundary. Fragmentless reload begins GET-only and offers explicit session recovery; the sidebar owns route selection plus icon-only Worker controls, model tests use a complete catalog selector with manual fallback, notices are fixed overlays, and Provider duplication copies no secret or lifecycle state. Setup uses test-time CAS selection without Worker start; explicit activation uses production start-on-activate semantics. Forwarding Records is disabled and inert.

## Lifecycle

- Initial selection: a successful CLI-requested compatibility test → require Worker stopped if no provider is active → compare-and-set null `activeProviderId` → report `workerStarted: false`. A concurrent or later successful test observes an existing active provider and does not replace it.
- Codex bootstrap: lock and inspect the selected Codex binding → skip repair for the same effective URL → otherwise publish exact backups and pending journal → publish fixed config → repair rollout/SQLite provider metadata → verify config, lock, history, and directory durability → clear the discoverable pending state.
- Explicit activate/switch: validate profile → resolve secret → persist `activeProviderId` → apply snapshot generation N+1 to a running Worker or start a stopped Worker → require acknowledgement and health.
- Stop: gracefully stop only the proxy Worker and release `127.0.0.1:15100`; keep the Supervisor/Admin control plane available on `127.0.0.1:15101`.
- Shutdown: stop the Worker if needed, verify Supervisor identity, and exit the Supervisor control plane.
- Restart: mark restarting → ask worker to drain → enforce timeout → wait for exit and port release → spawn → send active snapshot → require health success.
- Crash: record sanitized error → back off 250/500/1000/2000 ms for the first four crashes in a rolling 60-second window → enter `failed` immediately on the fifth crash. The exponential schedule remains capped at 4000 ms, but that fifth in-window delay is not executed.

## Storage and Deployment

- Package remains distributed through npm.
- The landed path contract reserves `~/.codex-remote-proxy/providers.json`, `provider-model-cache.json`, the lower-level injected adapter path `secrets.json`, `state.json`, `control-token`, `activity.jsonl`, and `supervisor.log`; ordinary Supervisor startup does not select `secrets.json`.
- Provider metadata: `~/.codex-remote-proxy/providers.json`, atomically replaced with mode `0600` where supported after complete document validation.
- Provider model catalogs: `~/.codex-remote-proxy/provider-model-cache.json`, independently validated as schema 1 and atomically replaced with mode `0600`; it contains no credential or credential reference.
- Anonymous Metrics: `~/.codex-remote-proxy/metrics.json`, independently validated as schema 1, capped at 32 MiB, retained for seven UTC days, and atomically replaced as private reconstructable state; it contains no per-request record or Capture payload.
- Supervisor runtime metadata: `~/.codex-remote-proxy/state.json`, atomically written with mode `0600` after Admin readiness and removed only by the owning supervisor instance.
- Credentials: public Supervisor startup requires the native OS store. Native loader or operation failure is a safe backend-unavailable error. `~/.codex-remote-proxy/secrets.json` belongs only to trusted injected lower-level use today; the UI, CLI, and Admin API cannot select it. A future public consent path requires L3 review, and no credential migration or native-operation replay is implicit.
- Activity events: implemented bounded private JSONL without request/response bodies.
- Codex configuration creation/replacement holds an exact-schema sidecar lock and uses file plus parent-directory `fsync`. Locks carry acquired/prepared/completed ownership and transition hashes; only an exact managed lock whose owner is provably dead and whose config/pending state matches may be ownership-checked recovered. Foreign, live, unknown, or conflicting locks remain blockers. A missing parent/config is created with POSIX `0700`/`0600`, no backup/history scan, and target/parent identity revalidation. Existing files receive a no-follow fsynced adjacent backup before atomic mode-preserving replacement.
- A history transition fsyncs private exact snapshots and `pending.json` before config publication. Rollouts are replaced only when backed bytes/identity still match. SQLite candidates are locked in stable order with `BEGIN IMMEDIATE`; a second identity-checked connection performs online backup while the lock connection remains open, and only the backed rowid set is updated. New/changed resources are deferred to a pending retry. Every failure after target-config publication is committed-degraded and retains pending state.
- Provider-registry mutation holds an exclusive `0600` sidecar lock across disk reload, complete validation, same-directory temporary-file `fsync`, `chmod 0600`, rename, and in-memory replacement; validation or persistence failure leaves the prior in-memory document unchanged. Bounded cleanup preserves primary errors and distinguishes a durable committed/degraded result from a retryable failure; permanent residual locks require explicit repair and restart and are never auto-removed.
- File-credential mutation follows the same conservative durable-commit rules while using a strict schema-version-1 secret-only document. Reads validate the parent and path before opening, verify descriptor identity, and never read secret bytes by path. An exclusive gate covers mutation. Release atomically renames the canonical gate to a unique claim, verifies and removes only that claim, and never deletes the canonical path. The canonical primary lock remains present throughout gate claim validation, so a competing instance that acquires the empty gate still reports busy; foreign or uncertain gate state must prove a canonical blocker before primary release, otherwise the primary lock is retained. Foreign or permanent claimed primary locks likewise restore a nonempty canonical blocker. Permanent secret-temp cleanup failure records uncommitted degradation and stops later mutations before another lock opens. Public errors contain no reference, secret, path, or file bytes.
- The same responsive bilingual three-file static UI is packaged on every platform. macOS and Windows are the initial desktop UI priorities, mobile-width overflow and keyboard behavior are deterministic local gates, and Linux retains full supervisor/CLI support; real platform acceptance is pending remote workflow evidence.

## Risks

- Credential backend differences across platforms.
- Atomic activation and in-flight request correctness.
- Port release races during restart.
- Localhost CSRF and DNS-rebinding-style attacks.
- Safe migration from the existing flat secret-bearing configuration.
- Provider compatibility tests never follow redirects; 3xx is a stable failure so custom authentication cannot be forwarded to another origin. Active profiles reject every update and deletion until another provider is activated, regardless of worker state.
- Provider model discovery shares the same no-redirect credential boundary, caps the response at 1 MiB, rejects a complete credential reflected inside any model ID, and retains only validated IDs. Providers that omit `/models` remain testable with a manually supplied model.
- CLI name selection is convenience rather than an atomic Admin selector. List resolution plus one per-ID snapshot revalidation rejects a rename observed before dispatch, but a concurrent rename after that second read remains a residual race; automation requiring atomic identity must use immutable `--id`.
- Provider-service activation persists the candidate active ID, reconciles committed/degraded persistence from the registry, marks the worker attempt before sending, and applies one selected credential through a strictly increasing snapshot. A health failure or rejected acknowledgement is treated as an unknown worker commit and restores the prior profile with a newer confirmed generation (`1 -> 2 -> 3`); rollback uncertainty is degraded and requires explicit repair.
- History repair requires Codex fully stopped. CRP rejects existing unsafe SQLite sidecars, but an external process creating a new sidecar concurrently remains outside CRP's config lock; real-home corpus size, 300-second bootstrap sufficiency, storage growth, and interruption time remain L3 operational evidence. The URL-only trigger deliberately does not rewrite provider-name-only changes at the same effective URL.

Deterministic integration and browser tests cover these areas locally. D1 composes `runCli -> SupervisorClient -> Admin -> registry/provider service -> WorkerManager -> real forked worker -> loopback upstreams`, including in-flight A/B switching and same-port restart, while injecting only the credential adapter and upstream. D1 remains distinct from production D2.

The final local macOS D2 used the production native-keyring adapter and login Keychain, real Dusapi upstream, real CLI, and detached Supervisor. Provider test, activation, proxy start, real `/responses` HTTP `200 OK`, health, restart, stop, shutdown, and cleanup passed; restart preserved the Supervisor PID and replaced the worker PID. Separate clean-home detached evidence also passed. This completes local core acceptance. Remote macOS/Windows/Linux native-service evidence, real-home migration/rollback, cross-platform hardlink/`O_NOFOLLOW`/ACL and process behavior, macOS/Windows visuals, and localhost browser launch still require platform evidence and L3 expert review before release. Broader child-process environment minimization is independent future L3 hardening, not a local-core blocker.
