# Decisions

| Date | Decision | Context | Consequences |
| --- | --- | --- | --- |
| 2026-07-10 | Use `iterate` harness mode | Existing v0.2.2 project is being expanded | Preserve current behavior while adding living contracts |
| 2026-07-10 | Target ordinary users first | CLI-only setup is a product barrier | Add guided local Web UI while retaining CLI |
| 2026-07-10 | Use Supervisor + Proxy Worker | Reliable restart and stable management access are required | Adds IPC/state coordination but isolates lifecycle |
| 2026-07-10 | Keep Codex provider as `OpenAI` | Thread metadata and listing are provider-bound | Existing history remains visible during upstream switches |
| 2026-07-10 | Keep a fixed loopback proxy address | Rewriting Codex config on every switch is disruptive | Provider activation happens inside CRP |
| 2026-07-10 | Prefer native credential stores | Product will handle multiple long-lived API keys | Platform adapters and L3 review are required |
| 2026-07-10 | Use guided utility console UI | New users need onboarding; experienced users need fast switching | First-run wizard transitions to low-density dashboard |
| 2026-07-10 | Keep Admin API loopback-only | Management actions expose credentials and process control | Reject remote binds and enforce browser-origin protections |
| 2026-07-10 | Defer remote access and failover | They expand security and operational scope | MVP stays local and single-active-provider |
| 2026-07-13 | Ship complete `en` and `zh-CN` dictionaries in the static app | The ordinary-user UI must support English and Simplified Chinese without widening the asset allowlist | Only explicit `crp.locale` selection persists; all other browser state is memory-only |
| 2026-07-13 | Make valid-cookie reload without a launch fragment GET-only | A reload must not retain the control token or silently regain mutation authority | Users can inspect state but must reopen with `crp ui` before changing it |
| 2026-07-17 | Permit explicit management recovery inside a still-valid cookie session | Requiring a new CLI launch after every refresh made the local Web console unnecessarily inert | Reload remains GET-only until the user acts; recovery is exact-origin, uses a non-simple header, rotates session/CSRF, preserves absolute expiry, and never re-reads the control token |
| 2026-07-14 | Require exact package and real native-backend release gates | Broad tarball checks and fallback-capable smoke tests can provide false assurance | The package has a reviewed 30-file allowlist, and each platform must prove its intended credential service before release |
| 2026-07-14 | Require native credentials at the public Supervisor boundary | Per-provider fallback consent could not safely select the startup backend | UI, CLI, and Admin expose no file-backend control; lower-level file storage is trusted-injection only pending future L3 startup consent |
| 2026-07-14 | Make `init` a strict alias of `ui` | Legacy secret setup persisted credentials in flat configuration | `init` accepts only `--no-open`/`--json` and rejects legacy options or positional input before discovery and writes |
| 2026-07-14 | Keep diagnostic export as a metadata-only compatibility path | The route name predates the implemented behavior | `/diagnostics/export` returns in-memory `{ created, generatedAt, eventCount }` and creates no bundle or file |
| 2026-07-14 | Pause Web refinement and make core CLI proof the active slice | Core behavior must be proven before additional management-page polish | Freeze Web source/E2E; implement and verify clean-home CLI, production-component composition, and real live smoke first |
| 2026-07-14 | Extend the existing shared core without a setup aggregation endpoint | CLI and Web already share versioned Admin operations and future Web work must not require a core rewrite | Preserve Admin `/api/v1`, registry schema 2, Supervisor/worker boundaries, fixed `OpenAI`, and `127.0.0.1:15100` |
| 2026-07-14 | Create a missing Codex config during explicit bootstrap/start | A clean home currently fails before CRP can configure Codex | Privately create the parent and atomic `0600` file, create no backup for a missing source, and preserve existing-file backup/mode/idempotency behavior |
| 2026-07-14 | Localize human CLI output but keep machine contracts language-independent | CLI needs English and Simplified Chinese without destabilizing automation | Resolve `--locale` and locale environment variables; keep JSON keys, codes, enums, messages, and actions stable |
| 2026-07-14 | Require deterministic composition and a separate real live smoke | Module tests or loopback/injected integration cannot prove native keyring and external-provider behavior | Local core completion requires both gates plus redacted cleanup evidence; both now pass |
| 2026-07-14 | Retain `provider add --api-key <KEY>` for now | The user deferred credential-input redesign | Record argv/history exposure as a known risk and revisit it later; it does not block local core completion |
| 2026-07-14 | Keep D1 and D2 evidence claims separate | A production-component loopback chain and detached lifecycle alone do not prove native credential retrieval or external forwarding | D1 remains deterministic evidence; the final production native-keyring and real-upstream D2 run completes the local core gate |
| 2026-07-14 | Separate discovery and operation timeouts | Reusing the 2-second discovery probe caused a successful real provider test to surface as `SUPERVISOR_UNAVAILABLE` | Probe `/status` for 2 seconds, then return a client with a 30-second normal-operation timeout |
| 2026-07-14 | Join proxy targets through parsed URL components | String concatenation turned a root base ending in `/` plus `/responses` into `//responses` | Preserve base paths, encoded request paths, and combined queries while emitting one path separator |
| 2026-07-14 | Distinguish local core completion from release completion | macOS D2 can pass while other platform and L3 evidence is still absent | Mark the local core gate complete without weakening cross-platform native, filesystem/ACL, visual, migration, or expert release gates |
| 2026-07-14 | Use a one-shot strict contract for detached startup failures | Readiness polling collapsed a safe migration conflict into `SUPERVISOR_START_TIMEOUT`, while raw child errors could expose secrets | Allow only static `MIGRATION_INPUT_INVALID` and generic startup contracts over startup IPC; reject all other payloads and keep real-home conflict resolution operator-controlled |
| 2026-07-15 | Repair CLI human output and layered help without changing machine or lifecycle contracts | Real acceptance proved provider operations and hot switching but found generic list/status text, missing subcommand help, and ambiguous stop/alias expectations | Render existing safe public state, resolve layered help before discovery, keep `stop` Worker-only and `shutdown` Supervisor-wide, retain compatibility aliases, and recommend only `ui`/`start` |
| 2026-07-16 | Compose optional provider add-and-test as two durable stages | A saved provider is still useful when compatibility testing fails or the test request cannot complete | `provider add --model` creates first, reports the follow-up result, and never compensates by deleting the committed provider |
| 2026-07-16 | Keep Admin provider routes ID-addressed while adding CLI name selectors | Opaque IDs are stable but hard for operators to remember; provider names are already unique case-insensitively | CLI test/activate/delete/models requires ID XOR name, resolves through the public list, and revalidates the selected ID/name snapshot before the operation; this is not an atomic server-side name API, so concurrent automation should use ID |
| 2026-07-16 | Persist provider model catalogs outside registry schema 2 | Future UI model selection needs reusable discovery, but widening provider profiles would force an unrelated schema migration | Add independent strict schema-1 `provider-model-cache.json`, authenticated bounded no-redirect refresh, complete-credential echo rejection, cache-only reads, source-fingerprint invalidation, and last-good preservation |
| 2026-07-16 | Make first-provider selection explicit, first-wins, and Worker-free | A successful first test should remove a redundant activation step without making a test unexpectedly start the proxy | CLI tests send `activateIfNone: true`; Admin defaults false; a stopped-Worker registry compare-and-set selects only the first success and reports `workerStarted: false` |
| 2026-07-16 | Default help to English and remove redundant startup aliases | The project targets global users and three names for two workflows made the CLI look larger than it is | Only explicit `--locale zh-CN` localizes help; `init`, `install`, and `setup` now return side-effect-free `CLI_COMMAND_REMOVED` guidance to `ui` or `start`, superseding their 2026-07-14/15 compatibility status |
| 2026-07-16 | Repair history only for a Codex-level effective URL transition | Codex history metadata is provider-bound, while routine CRP upstream switches must remain internal | Read root `model_provider` and its corresponding `base_url` from one locked snapshot; different or missing existing URLs trigger repair, same URLs do not even if the provider name changes, and CRP provider operations never trigger it |
| 2026-07-16 | Use durable forward recovery instead of cross-store rollback | Config, rollout JSONL, and multiple SQLite stores cannot form one atomic transaction | Snapshot exact write sets, atomically validate backups, fsync journal and affected directories, retain source/target hashes plus a discoverable pending state, and resume on later bootstrap |
| 2026-07-16 | Distinguish config-only and history-pending committed uncertainty | Config publication may commit even when no history row requires repair, so claiming pending would misdirect recovery | Return `CODEX_CONFIG_COMMITTED_DEGRADED` with `pending:false` for config-only uncertainty and `CODEX_HISTORY_REPAIR_COMMITTED_DEGRADED` with `pending:true` only when a discoverable repair blocker remains |
| 2026-07-16 | Gate every Worker spawn on strict Codex readiness | Pending or invalid selected bindings must not be bypassed through activation, direct lifecycle routes, or crash recovery | No-follow/identity/selected-binding status plus one FIFO bootstrap/readiness gate protects activation, start/restart, and unexpected-exit recovery; queued recovery rechecks cancellation before spawn |
| 2026-07-16 | Resume Web work with a clean React replacement | The approved v0 direction is useful, but its Next.js runtime and the legacy UI do not fit the local three-file package | Author responsive TypeScript/React under `node/ui-src/`, build with Vite, and continue publishing exactly `index.html`, `app.js`, and `styles.css`; this supersedes the 2026-07-14 Web pause |
| 2026-07-16 | Keep Overview Metrics anonymous and independent from Capture | Operational trends are useful before detailed forwarding-record management is safe or in scope | Aggregate strict hourly result, observed-Token, model, Provider, and latency histograms for 24h/7d; never persist per-request IDs, URLs, headers, bodies, sessions, credentials, raw errors, or exact timings |
| 2026-07-16 | Use test-time CAS selection only in conditional Setup | First setup needs an active Provider before Codex preparation without surprising the user by starting the proxy | Setup runs save → test with `activateIfNone` → Codex bootstrap/history repair → start; explicit Provider activation remains the production switch operation and starts a stopped Worker |
| 2026-07-16 | Reserve Forwarding Records without implementing Capture management | The user wants the information architecture to anticipate traffic records, but Capture management is outside this MVP | Show one disabled bilingual navigation item with no route, API request, mock data, payload view, export, purge, or Capture toggle |
| 2026-07-16 | Accept V8 locally only with matched visual and full browser evidence | Presence of a rebuilt UI does not prove responsive, security, or v0-aligned behavior | Require exact full/package/audit gates, Chromium 33/33, English/Chinese 1440/1024/390 coverage, and a same-state side-by-side comparison before marking V8 locally complete |
